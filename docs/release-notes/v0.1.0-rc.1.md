# Veil Terminal v0.1.0-rc.1

First release candidate with the SSH engine running inside a protected
Microdroid VM.

## What's in this release

- **VM-first engine.** The normal path runs the Rust engine in a protected
  Microdroid VM. The native process engine remains available and selectable,
  and is not silently substituted when the VM fails.
- **Separate VM host APK.** `io.github.franticplant.veil.vm` owns the AVF
  permissions, boots the fixed payload, and has no `INTERNET` permission and no
  access to the app's SSH keys.
- **Keys stay in the app.** SSH private keys are in Android Keystore, using
  StrongBox where available. The guest asks the app to sign a login; the
  private key never enters the VM.
- **Host-key policy.** Trusted host keys are owned by the frontend and apply to
  both native and VM sessions. A changed key is refused.
- **Configurable VM memory.** Guest RAM defaults to 128 MiB and is changeable in
  Settings for the next Veil start.
- **Broker lifecycle.** Per-session broker relays are reclaimed when a session
  closes; the VM engine remains running for the next session.
- **Observability.** The VM host process and relay counters are visible through
  devd, `veil-ctl top`, and `vm.stats`; `veil-ctl logs vm` exposes the VM
  console and payload output.
- **Release packaging.** The `.vm` APK is built, signed, checked against the
  pinned Veil signer, and shipped with the main app.

## Installing VM mode

1. Install the main Veil APK.
2. Install the `.vm` APK.
3. Grant the one-time AVF permissions to the VM package:

   ```sh
   scripts/grant-avf
   ```

   Or grant them directly with adb:

   ```sh
   adb shell pm grant io.github.franticplant.veil.vm android.permission.MANAGE_VIRTUAL_MACHINE
   adb shell pm grant io.github.franticplant.veil.vm android.permission.USE_CUSTOM_VIRTUAL_MACHINE
   ```

4. Open Veil → Settings → Engine → **VM (Microdroid)**, then restart Veil.

VM mode needs a device with AVF/Microdroid support. It was validated on a
Pixel 8 running GrapheneOS. If the VM is unavailable, Veil reports the failure
and leaves the native engine available as an explicit choice.

## Caveats

- This is a **release candidate**, not a stable release. Expect rough edges.
- The first VM connection takes several seconds while the VM boots. Later
  sessions are much faster.
- The VM host is a separate package. It is optional for native mode, but
  required for VM mode.
- The main app currently holds `INTERNET` and the SSH signing authority. The
  planned `.net` and `.vault` separation is not part of this release.
- The VM package has no `INTERNET` permission and never receives private keys.
- Total memory use includes the app, the VM host, and the guest; this release
  does not claim a combined memory budget.
- Native mode has weaker isolation than the protected VM. It remains a useful
  comparison and recovery path.

## Verification

Every release file is signed with the pinned Veil key. Checksums and GitHub
attestations are attached to the release. Verify a download with:

```sh
sha256sum -c SHA256SUMS
gh attestation verify <file> -R franticplant/veil-terminal
```
